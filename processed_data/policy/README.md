# Source-linked policy draft

[`policy_rules.json`](policy_rules.json) is generated by
[`scripts/build_policy_rules.py`](../../scripts/build_policy_rules.py) from
[`raw_data/guidelines.json`](../../raw_data/guidelines.json). The script
checks that the three return subflows share the same action text and that the
two promo subflows share theirs before combining them. The eight selected
intents become 22 structured rules, each with an `evidence` array containing
the original guideline text and its source path. `kb.json` and
`ontology.json` help check names and action categories, but are not the
source of the policy sentences.

This is a **project-authored transcription**, not policy JSON supplied by
ABCD. The `status` in the file remains `draft_for_user_review`. Among the
unresolved source issues are date-boundary definitions, ambiguous Oracle
Yes/No wording, a Bronze cancellation instruction conflict, and unspecified
behavior after a customer refuses a $20 upgrade charge. The mock Oracle does
not grant authority to issue replacement codes.

The backend policy gate uses this file together with business SQLite facts,
but conservatively blocks actions where required evidence or authority is
missing. The model's policy citation or proposed payload alone never
authorizes an action.
